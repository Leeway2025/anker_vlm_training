# 压缩与输入缩减报告(不含 t80 held-out track)

日期:2026-08-16
范围:Gemma-4 E2B-it VLM LoRA 适配器的**输入缩减**(soft-token 数)与**模型压缩**(适配器量化打包)两条轴。
不含:B 机 r64_t80 held-out track(单独另评,不在本报告)。
验收线:RT ≥ 87.91 且 SubKS ≥ 80.42(class_diag 口径,校准后,n=11022);SubKS 为主,两项都须过。
交付口径:fit-full / 当前测试集过线(客户已确认 128、64 均按此口径,不管 OOF)。

---

## 一、输入缩减(input reduction)

### 现状与目标
- 视觉编码每帧产出 64 个 soft token;16 帧 = **1024 token** 进入冻结 LLM。
- 目标:把进 LLM 的 token 数压下来(降显存/降时延),同时不破坏基座(基座 LLM 全程冻结,只训 LoRA + 投影/重采样)。

### 方案:K=32 固定
- 每帧 **64 → 32** soft token(2× 缩减)。
- 16 帧:**1024 → 512** token(2× 缩减)。
- K=32 为**固定**值(客户此前已否 K=48;bbox priors、DoRA 也被否 —— Rockchip NPU 不支持)。

### 代价:512-token 容量墙
- 512 token 承载能力有限,r64 的 SubKS **诚实上限约 80.15**,已 **8 次独立验证**(r64_t80 是第 8 次)。
- 误差结构根因:49.5% 的巨类 m 黑洞 + 同父兄弟子类混淆;训练/损失/监督/校准四轴全部拉满仍触顶 = 512-token 容量墙。
- 越墙手段:提高 LoRA rank(r64 → r128),用更大适配器容量把 SubKS 推过 80.42(见下)。**输入缩减轴不动**(K=32 保持),越墙靠的是压缩轴上的 rank/量化取舍。

> 关键区分:**输入缩减(K=32,运行时 token 数)** 与 **适配器压缩(权重量化)** 是两条独立轴。K=32 决定进 LLM 的 token 数;量化决定落盘的适配器体积。二者互不替代。

## 二、模型压缩(adapter quantization / packing)

**只算适配器**,基座 LLM 冻结不计入 ≤122MB 预算。

### 起点(fp32 主权重)
- r64:`train_params_best.npz` **484MB** fp32
- r128:soup `model.npz` **964MB** fp32

### 压缩技术栈
1. **省零叶(zero-omission)**:全零 LoRA 叶不落盘,**位精确无损**。r64 省了 236 个全零叶。
2. **逐通道 int8(per-channel int8)**:每通道独立 scale,精度损失极小。
3. **混精逐张量打包(mixed_prec_pack.py)**:默认 int4;按 int4 量化误差把**高误差叶**在预算内提升到 int8,择优混合。`--budget 1` 可强制 0 提升 = 纯 int4。

### r64 路线(**交付**)
- **逐通道 int8 + 省零叶**:484MB fp32 → **88.19MB**(84.10 MiB)。压缩 **5.5×**,进 122MB 预算。
- 精度(fit-full,校准后,n=11022):**RT 88.13 / SubKS 80.65 —— 双过线** ✓
- 参考 OOF(严格无泄漏,非交付口径):87.82 / 80.14。
- sha256 = `94df663e23f8c3df1524d57d5c4fe7fe4cfde0478bdcf1155e118cda32b43076`
- 文件:`A_ns_repair_r64/model_int8_packed.npz`

### r128 路线(压缩取舍对照)
| 变体 | 体积 | RT | SubKS | 结论 |
|---|---|---|---|---|
| 逐通道 int8 | 242MB | ~—— | ~80.6 | **超 122MB 预算** ✗ |
| 纯 int4(省零) | 84.9MB | 87.83 | 80.28 | 进预算但 **SubKS 不过** ✗ |
| int4 group768 | ~85MB | 87.91 | 80.22 | SubKS 不过 ✗ |
| int4 mse | ~85MB | 87.97 | 80.16 | SubKS 不过 ✗ |
| **混精 mixed_h(int8+int4)** | **122.2MB** | **88.12** | **80.68** | **进预算且双过**(OOF 也过 80.48)✓ |

- r128 想**同时**过线 + 进 122MB,**必须 mix**(混精 mixed_h)。
- 不 mix 的 r128:int8 过线但 242MB 超预算;int4 进预算但 SubKS 卡 80.16~80.28,过不了(int4 把高误差叶压太狠,校准补不回来)。

---

## 三、结论

1. **输入缩减**:K=32(1024→512,2×)已落定;代价是 512-token 容量墙(r64 SubKS ≈80.15 上限,8 次验证)。
2. **模型压缩**:
   - **r64 int8(88MB,80.65)是干净的过线 + 进预算交付路**(不依赖 mix)。
   - **r128 若可 mix,mixed_h(122MB,80.68)可交付 128;若不可 mix,r128 无法既过线又进预算**,只剩 r64 int8 一条路。
3. 待客户确认:"mix 不要" 是 NPU 部署硬限制(→ 128 不可交付,仅 r64 int8)还是偏好(→ mixed_h 可交付 128)。

*(本报告不含 t80 held-out track;该 track 单独评测,见 eval_report_heldout.txt。)*
