# 技术路径 B:输入 Token 缩减达标(1024→512,prefill −38%)

目标:16 帧 × 64 soft-token = 1024 → 512 进 LLM,NPU 端到端延迟约 −26%,精度损失可被路径 A 吸收。
与体积压缩路径(PATH_compression_size.md)正交。

## 达标配方(按执行顺序)
1. **选择而非合并**:保留原 token、丢弃低分 token(位置空洞由 RoPE 天然处理)。
   合并类(ToMe/hyb 均值)三次实测均负——语义 soft-token 不宜均值混合。
2. **打分器:运动+范数启发式**(零参数,CPU 可算)
   逐 token 分数 = 帧间运动幅度 + 特征范数;实现于 data.py `_compress_soft_tokens`。
3. **预算分配:dyn 全局 512 竞争**(交付口径)
   所有帧的 token 进全局池按分竞争 512 名额,每帧保底 8 防时序断档;
   比每帧固定 K=32 更优(r64 档 +0.32)。env:`TOKEN_COMPRESS_MODE=dyn SELECT_TOKENS_K=32`。
4. **训练适配是主要成本来源的解药**:模型必须在压缩口径下(重)训练——
   零样本换选择器一律吃训推不一致亏(实证 −1.28 量级);
   uniform 训练 + dyn 推理可行(dyn 是 uniform 的子集式扰动)。
5. **哨兵与图形状**:layout 保留 1024 视觉槽,压缩只填前 512、其余 -2 sentinel,
   序列长恒 1359 → LLM 图形状不变,NPU 只需一次改图。
6. **NPU 三段式部署**:编码器 NPU 图 → 选择器 .so(CPU,<1ms,可 OTA 热更)→ 固定 512 LLM NPU 图。

## 上限与代价的实证(为何止步于启发式)
- 神谕测试:按老师梯度显著性选 = 80.01~80.09 ≈ 运动启发式 80.12 → **"选哪512个"已饱和**。
- 受害集 K=48 反事实:368 条压缩致错样本给 +50% token 仅修复 37.5% → 非信息不足。
- 压缩税:满秩 −0.30 / r64 −0.49(容量越小税越重)→ 税由路径 A 的秩/量化余量吸收。
- 学习式打分头(task-loss)不可行:硬 top-k 零梯度 + 冻结底座双重阻断;
  可导替代(软选择/直通/显著性回归)基建已留(重采样器走 tok 通道,单测全过)但因上限饱和未投产。

## 已证无效(勿复投)
hyb/hyb2/ToMe 合并、dynseg 逐帧预算、TOKEN_DILATE/ATTNPROXY 打分变体、
task-loss 学习头、8 帧下采样(f8 适配反退步)、空间增强(与满帧正方形前提冲突)。

## 交付口径
三个交付包全部 K=32:r64-int8(dyn)、r128-int4(topk)、mixed_h(K=32);
prefill 1359 恒定,视觉 token 512,decode 不变。
