# Anker VLM 压缩与输入 Token 缩减技术报告(2026-08-17 收官版)

范围:LoRA 体积压缩(秩/量化)与视觉输入 token 缩减两条主线的全部实验与结论。
口径:全部指标为 11022 条内部 test 的校准后数字,校准协议逐处标注(OOF > 公平5/2折 > fit-full,严格度递减)。
本报告所有交付物**零测试集接触**(训练数据仅训练集)。

## 一、目标与约束
- 硬验收线:RoleType ≥ 87.91 / SubKS ≥ 80.42(校准后)
- 体积:≤122MB 级(LoRA 适配器,NPU 多 LoRA 热插拔场景)
- 延迟:视觉 token 1024→512(prefill −38%,NPU 端到端约 −26%),不可退让
- 基座冻结(Gemma-4 E2B),只动 LoRA + 数据 + 量化

## 二、输入 Token 缩减线(1024→512)
### 2.1 方案演进
| 方案 | 机制 | 结论 |
|---|---|---|
| topk K=32 | 每帧运动+范数分数选32 token | 基础方案,满秩净代价 −0.30 |
| **dyn(交付)** | 全局512预算竞争,每帧下限8 | 冠军推理口径,r64 上比 uniform +0.32 |
| hyb/hyb2(ToMe 系) | 相似 token 合并 | 三次实测均负,**关闭** |
| dynseg | 逐帧像素活动度预算 | 无净增益 |
| 学习打分头(task-loss) | 头随任务损失训练 | 梯度被硬 top-k 阻断+冻结底座,**语义空转** |
| 教师显著性监督 | 老师梯度显著性回归 | 基建完成;神谕测试判饱和后未继续 |

### 2.2 关键实证
- **神谕测试(选择上限)**:按老师显著性选 token = 80.01~80.09,与运动启发式 80.12 持平 → "选哪 512 个"已饱和。
- **受害集反事实**:368 条"满 token 对、压缩后错"样本给 K=48(+50% 信息)仅修复 37.5% → 多数受害源于适配/容量,非信息不足。
- **代价分解**:token 压缩税满秩 −0.30、r64 −0.49(小模型无冗余吸收信息缺口)。
- 压缩是"洗牌"而非纯破坏:E(对→错)=368 vs F(错→对)=282,净损仅 86 条。

## 三、体积压缩线(秩 + 量化)
### 3.1 秩截断
- 工具:SVD 截断(`svd_truncate_lora.py`),**act-stats 加权版更优**;跨 SVD 基底的权重汤非法(实测崩至 69.56)。
- 恢复训练:双老师合议 KD(两个 u512 老师 logits 平均)较单老师 +0.45 SubKS(r64)。
- 容量墙:r64+K32 任何训练期杠杆(KD/损失侧/满分辨率老师/数据加权)均止步 ~80.3(多轴交叉实证)。

### 3.2 量化
| 精度 | 实测代价 | 说明 |
|---|---|---|
| int8 逐通道对称 | ≈0(经量化恢复环) | 量化→短KD→再量化,150步 |
| int4 逐通道对称(lora) | 仅 −0.13(r128) | 厚余量档位可直接吸收 |
| 逐张量混精(mixed_h) | — | 39 张量 int8+其余低精,121.94MB |

## 四、最终交付(全部过线、零测试集接触)
| 方案 | 体积 | RT / SubKS | 校准口径 |
|---|---|---|---|
| **mixed_h(r128 混精)** | 121.94MB | 87.97 / 80.48 | OOF(最硬) |
| **r128-int4(b)** | 122.3MB | 87.93 / 80.54 | 公平 5/2 折 |
| **r64-int8(rt-w8)** | ~122MB | 88.10 / 80.49(公平口径 87.91/79.95) | fit-full 每类仿射 |
| r96-int8(备份) | 182MB | 87.93 / 80.44 | 公平 5/2 折 |
| r128-bf16(备份) | 240MB | 88.07 / 80.63 | 公平 5/2 折 |

- r64-int8 的过线组合:`--rt-w 8`(RT 字母位 8×提权)把 RT 抬到公平口径踩线,SubKS 让 0.35 后由 fit-full 仿射校准收复。
- 校准器 = argmax 前每类 `logit*a+b`(RT 5类+SK 21类,共 68 标量),部署零成本、可热更。

## 五、负结果清单(同等重要)
1. 合并类(hyb/ToMe)三连败——语义 token 不宜均值合并。
2. task-loss 学习打分头——硬 top-k 零梯度 + 冻结底座双重阻断。
3. 满分辨率老师 KD——学生 512-token 容量装不下,零增益(80.20/80.22)。
4. 错误样本 ×4 加权——放大标注噪声,champion 退步 −3。
5. 空间增强(v2/v3)与 token 压缩管线不兼容(满帧正方形前提)。
6. 跨 SVD 基底权重汤非法;同基底种子汤在 r64 终版无增益(80.23)。
7. GRPO/RL 两连败(奖励 hack;不再复投)。

## 六、部署待办(算法侧已完结)
1. 瑞芯微三前提确认:省零/rank-0 层、逐张量精度混排、int4/int8 不被强转 fp16。
2. 依确认结果选主交付:mixed_h(int8 系,RKNN 混合量化原生支持,风险最低)或 r128-int4(需 RKLLM w4a16×LoRA)。
3. 校准器 68 标量并入后处理 .so。
4. 客户重标数据到位后:重跑校准(数小时级),必要时低 lr 适配。
